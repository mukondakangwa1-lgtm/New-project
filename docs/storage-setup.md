# Storage Setup — PostgreSQL, SQLite, MinIO

Digital Campus uses three storage tiers. This document explains what each
holds, how the stack boots them automatically, and how to install, configure
and secure them for real-world deployment.

## Division of labour

| Store | Holds | Runs |
|---|---|---|
| **PostgreSQL (pgvector)** | All relational data: users, courses, assignments, chats, memories, agent tasks, embeddings. Source of truth. | Production / Compose |
| **SQLite** | Same schema; single-file dev fallback and standalone single-box runs. WAL mode enabled automatically. | Dev, tests, local boxes |
| **MinIO** (S3-compatible) | Binary objects only: speaking audio (`audio/`), uploaded knowledge originals (`docs/`), avatars (`avatars/`), database dumps (`backups/`). | Compose / anything S3 |

The backend talks to storage through `app/core/storage.py`: `STORAGE_BACKEND
= auto` uses MinIO when `MINIO_ENDPOINT` is configured and falls back to a
local directory otherwise (one code path for both — local mode is also what
unit tests exercise).

```
┌─────────────┐   ┌──────────────────────────────┐
│   backend   │──▶│ MinIO bucket "kudos"          │  audio/ docs/ avatars/
│   (worker)  │   │  + versioning, scoped policy  │  backups/
│  (scheduler)│   └──────────────────────────────┘
│             │──▶│ PostgreSQL (pgvector)         │
└─────────────┘   └──────────────────────────────┘
```

## 1. PostgreSQL

### Install (Compose — recommended)
Everything is automatic: the `db` service uses `pgvector/pgvector:pg15`
(PostgreSQL 15 + vector extension) with a healthcheck. Credentials come from
the repo-root `.env`, generated by `make env-provision`:

```bash
make env-provision   # creates secrets in .env + services/backend/.env
make docker-dev      # or: docker-compose up -d --build
```

### Bare metal
```bash
sudo apt-get install -y postgresql postgresql-contrib   # Debian/Ubuntu
# or: brew install postgresql@15 / dnf install postgresql-server
sudo -u postgres psql -c "CREATE ROLE dc_user LOGIN PASSWORD 'strong-random'"
sudo -u postgres createdb -O dc_user digital_campus
```

### Secure configuration
- **Password policy**: 30+ random characters. `make env-provision` generates
  one; never commit `.env`.
- **Network**: in production Compose, `db` exposes **no host ports**;
  only the internal network reaches it. Dev binds `127.0.0.1:5432`.
- **Auth**: Postgres 15+ defaults to `scram-sha-256`. Keep it:
  `ALTER SYSTEM SET password_encryption = 'scram-sha-256';`
- **TLS** (public VPS): generate a server cert and set
  `hostssl all all 0.0.0.0/0 scram-sha-256` in `pg_hba.conf`, then
  `ALTER SYSTEM SET ssl=on` + restart. Inside the compose network the
  connection is already private, so TLS is only required when Postgres is
  exposed publicly (not recommended).
- **Backups**: the `backup-scheduler` service runs a daily `pg_dump` into
  MinIO `backups/` automatically and prunes to `BACKUP_KEEP` (default 14):

```bash
docker compose -f docker-compose.prod.yml exec backup-scheduler cat /var/log/cron.log
make backup          # manual dump (Postgres)
make backup-restore FILE=backups/digital_campus_....dump
```

- **Migration**: `make docker-prod-migrate` (Alembic) is the only supported
  way to change production schemas; `AUTO_CREATE_TABLES` must stay `false`.

## 2. SQLite

Nothing to install — it ships with Python. The backend auto-applies
production pragmas on connect (see `app/core/database.py`):

```sql
PRAGMA journal_mode=WAL;   -- concurrent readers without writer blocking
PRAGMA synchronous=NORMAL; -- fast + safe for WAL
PRAGMA foreign_keys=ON;    -- enforce FK integrity
PRAGMA busy_timeout=5000;  -- queue instead of failing on lock
```

Set `DATABASE_URL=sqlite:///./digital_campus.db` in `.env`
(`STORAGE_BACKEND` irrelevant — objects go to local disk in this mode).

### Securing SQLite
- Place the file **outside the web root** (default: backend working dir) and
  deny web-server reads:
  ```bash
  chmod 600 services/backend/digital_campus.db*
  ```
- Back it up with the stdlib (consistent snapshot, safe with WAL):
  ```bash
  cd services/backend && .venv/bin/python -m app.core.backup sqlite-dump
  ```
  When MinIO is reachable it is also pushed to `backups/`.
- Restore: stop the app, replace the db file with the snapshot (or
  `sqlite3 digital_campus.db ".restore <snapshot>.sqlite3"`), then restart.
- Never expose SQLite over the network; it is single-writer local storage.

## 3. MinIO (object storage)

### Install — Compose
Included as `minio` (server) + `minio-init` (one-shot bootstrap) in both
`docker-compose.yml` and `docker-compose.prod.yml`:

```bash
make env-provision
docker compose -f docker-compose.prod.yml up -d minio minio-init
docker compose logs minio-init   # should end with "storage bootstrap complete"
```

`minio-init` (deploy/minio/init.sh) automates:
1. creates bucket `kudos` (idempotent),
2. enables **versioning** on it,
3. creates the **scoped application user** from `MINIO_ACCESS_KEY`,
4. attaches policy `deploy/minio/app-policy.json` (read/write only inside
   bucket `kudos` — it cannot list buckets, delete other buckets, or manage
   users),
5. never touches the root account afterwards, so root credentials can be
   rotated or locked down.

### Install — bare metal (optional alternative)
```bash
wget https://dl.min.io/server/minio/release/linux-amd64/minio
chmod +x minio && sudo mv minio /usr/local/bin/
sudo useradd -r -s /usr/sbin/nologin minio-user
sudo mkdir -p /var/lib/minio && sudo chown minio-user /var/lib/minio
# Systemd unit uses Environment=MINIO_ROOT_USER=... (never CLI args)
```

### Secure configuration
- **Credentials**: `MINIO_ROOT_USER/PASSWORD` are bootstrap-only. The app
  uses the scoped `MINIO_ACCESS_KEY/SECRET_KEY` — root stays in the repo-root
  `.env` (gitignored, `chmod 600`).
- **Network**: production Compose exposes **no** MinIO ports; in dev the API
  (`9000`) and console (`9001`) bind to `127.0.0.1` only. If you must expose
  it publicly, use a reverse proxy with TLS and keep `MINIO_BROWSER=off`
  (already set in prod).
- **In transit**: backend→MinIO is on the private compose network.
  `MINIO_SECURE=true` + a reverse proxy with TLS is the public path.
- **At rest**: data lives on the docker volume; versioning keeps accidental
  overwrites/deletes restorable (`mc version`). For encryption at rest use
  `mc encrypt set sse-kms ...` against a KMS, or full-disk encryption on the host.
- **Policy**: only the scoped policy is usable by app credentials; test with:
  ```bash
  mc admin user list myalias
  mc admin policy list myalias
  ```

### Verify the whole path
```bash
make storage-verify      # round-trips a probe object through MinIO
make storage-status      # /api/v1/health/ready incl. storage check
```

### Disaster recovery
- Backup archives live in MinIO `backups/` (daily, pruned to 14).
- Offsite copy (recommended): mirror the bucket to a second location —
  `mc mirror local/kudos/backups/ remote/backup-bucket/backups/`.
- Restore Postgres:
  ```bash
  docker compose -f docker-compose.prod.yml exec backup-scheduler \
      /usr/local/bin/python -m app.core.backup restore /backups/<file>.dump
  ```

## Secret hygiene

| Secret | Where | Rotation |
|---|---|---|
| `SECRET_KEY` | `services/backend/.env` | app restarts |
| `POSTGRES_PASSWORD` | repo `.env` + `backend/.env` | create new role or ALTER USER |
| `MINIO_ROOT_*` | repo `.env` only | rotate daemon env + `mc admin user` |
| `MINIO_ACCESS_KEY/SECRET_KEY` | `.env` + MinIO server | `mc admin user start` |

`make env-provision` never overwrites existing values — safe to re-run after
deploying.
